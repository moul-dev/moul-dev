# Changelog: October 2026 (v2026.10.0)

This release hardens Moul's defaults after an embedding application audited them, cuts Moul's fixed cost per request, and adds Go hooks for programmatic writes. It also ships encrypted and unique fields, a configurable API prefix, custom MCP tools with OAuth for Gemini, and hardened realtime streams. Several changes alter behavior for non-admin callers; see **Upgrade notes** and the full [embedder upgrade guide](../docs/upgrade-2026-10.md).

## Security

- **Admin surface locked to root users and the admin key**: schemas, settings, file listing/deletion, workers, retry-jobs, visits, requests, feature flag management, metrics, the rules sandbox and MCP no longer accept tokens of ordinary auth collections (`403`). `GET /api/moul` is no longer public.
- **No credentials in URLs**: `?token=`, `?admin_key=`, `?adminKey=` and `?api_key=` are refused with `400` on every route; send `Authorization: Bearer` or `X-Admin-Key`.
- **Trusted proxies**: the client IP comes from forwarding headers only when the peer is a trusted proxy (`MOUL_TRUSTED_PROXIES`, default loopback only; `MOUL_CLIENT_IP_HEADER` for e.g. `CF-Connecting-IP`). Previously the first `X-Forwarded-For` entry, chosen by the client, keyed rate limits and the root IP allowlist.
- **Client filters and sorts**: a `?filter=` can no longer overwrite the `listRule`'s values (both used placeholders `p1…`); relation sorts are validated and quoted (they were SQL injection); `@collection` is refused in client filters (it could read any table, including `_rootUsers` and `_settings`); secret columns cannot be filtered, sorted or searched; relation paths honor the target's `listRule`.
- **Record responses**: `resetToken`, `resetTokenExpiresAt` and `oauthProviders` are no longer returned; other users' emails are hidden unless the record opts in through an `emailVisibility` bool field; `?expand=` applies the target's `viewRule`; realtime events are redacted per subscriber.
- **Existence**: a record the caller may not view answers `404` exactly like a missing one on get, update and delete; relation targets of a create are validated only after the `createRule` passes.
- **Ownership and bounds**: columns pinned by the `updateRule` (`owner = @request.auth.id`) cannot be reassigned; number fields store canonical numbers.
- **Files**: uploads and their record references are tracked (`_files`, `_file_refs`); `/storage` serves files of non-public records only with a signed URL (or to the uploader, a permitted viewer, or an admin) and answers everything else like a missing file; S3 is served through presigned redirects; file field values must point to the caller's own uploads.
- **Uploads**: members cannot upload HTML, SVG, XML, scripts or CSS; `file_allowed_types` narrows uploads; stored files are served with `nosniff`, a sandboxing CSP and as attachments unless they are media.
- **OTP**: 5 guesses per code, 20 failures per account per day, 30 per client network per 10 minutes (`429` with `Retry-After`). The `429` body carries a `reason`: `code` (request a new code) or `account` / `network` (wait). Codes are compared in constant time and no longer logged when they can be delivered.

## Realtime

- **Tickets instead of query tokens**: browsers exchange a bearer token for a 30-second single-use ticket (`POST /api/realtime/ticket`) and connect with `?ticket=`, or stream through `fetch()` with an `Authorization` header.
- **Mid-stream authorization**: every event re-evaluates the `subscribeRule` (or `viewRule`) for each subscriber; a record that leaves a subscriber's view arrives as a `delete`; a revoked or expired token ends the stream with `event: auth_expired`.
- **Backpressure**: each stream buffers at most 128 events and flushes with a 5-second deadline; a client that falls behind gets `event: slow_consumer` and is disconnected. With rate limiting on, a user may hold 15 streams and an IP 30 (`429` beyond; tune with `maxConcurrent` rules).
- **Cloak fields** are masked in events; `?reveal` on a stream is admin-only (`400` otherwise).
- **Benchmark**: `make bench-sse` and `make bench-sse-network` (`cmd/sse-bench`) run 100, 1,000 and 10,000 connections with leak detection and baseline comparison.

## Performance

Signed-in requests and polls no longer touch SQLite for auth, visits and schemas.

- **SQLite connections**: WAL, `busy_timeout`, `synchronous=NORMAL` and foreign keys now apply to every pooled connection (only one got them before, so the others failed with `SQLITE_BUSY` during any write), and idle connections are kept (`MOUL_DB_MAX_CONNS`, default max(4, CPU count)). In the embedder's benchmark, p95 dropped from 10 ms to 1 ms at 4 concurrent requests.
- **Write transactions**: every transaction starts with `BEGIN IMMEDIATE`, so read-then-write no longer fails with "database is locked" when another connection commits in between. Workers claim jobs in one `UPDATE … RETURNING`; the sign-in email enqueue retries while SQLite is busy.
- **Request log**: can be turned off, sampled or narrowed (`request_log_enabled`, `request_log_sample_rate`, `request_log_exclude_paths`), with configurable retention (`request_log_retention_days`, `visit_retention_days`); each batch is one transaction.
- **Revoked tokens and visits**: revocations are checked in memory (other processes' revocations within 60 s). Requests that cannot keep the visit cookie (API clients, server-side rendering, probes) no longer create a `_visits` row, and known visits are cached.
- **Collection schemas**: cached in process instead of re-read and parsed on every `/moul/*` request, expand and worker poll; changes from other processes or raw SQL are picked up within 1 s.
- **Photo pipeline**: at most `MOUL_IMAGE_CONCURRENCY` images (default half the CPUs) are processed at once; renditions are cut from the next larger size with a Linear filter (405 ms instead of 809 ms for a 12 MP JPEG on one core); images over 40 MP are refused from their header with `413`; uploads return `width` and `height`; `file_thumbs_async` moves renditions to a background job.

## Collections and fields

- **Encrypted fields (`cloak`)**: AES-256-GCM at the application layer, keyed from `MOUL_ENCRYPTION_KEY` (required once any collection has a cloak field). Responses mask values (`••••` plus the last 4 characters) unless the caller is an admin or asks with `?reveal=`; `searchable: true` adds an HMAC blind index for `=` and `!=` filters.
- **Unique fields**: `unique: true` on text, number, date, datetime, url and email fields creates a unique index and makes the field required; enabling it on a column that holds duplicates answers `400`.
- **camelCase everywhere**: custom field names must match `^[a-z][a-zA-Z0-9]*$` (`400` otherwise), and `_moul` timestamps are `createdAt` / `updatedAt`.
- **Readable record IDs**: generated IDs are `<singular collection>-<random>`, singularized with an English dictionary (`posts` → `post-…`, `people` → `person-…`).
- **Owner-only defaults for auth collections**: new auth collections get `id = @request.auth.id` for list, view, update and delete, and an open create rule for sign-up.
- **System tables** are created on first startup.
- **`PATCH /api/moul/:name` is a partial update**: only the properties in the body change. It used to rebuild the collection from the body, so every schema save from the console or TUI (`name`, `fields`, `rules`) dropped the collection's webhooks and reset custom auth email templates. `rules` merge key by key; `fields`, `webhooks` and `emailTemplates` replace the stored values when sent (`null` clears them, restoring the default templates).

## Go API and embedding

- **Record hooks**: `app.OnRecordBefore{Create,Update,Delete}` and `app.OnRecordAfter{Create,Update,Delete}` run for every record write, over HTTP or from Go.
- **Records API**: `app.Records()` creates, updates, deletes, reads and lists records through the full API pipeline (validation, rules, webhooks, realtime events, file tracking, hooks); `AsUser` applies collection rules as a user; `Notify` announces raw SQL writes to hooks, webhooks and realtime subscribers.
- **`app.WriteTx`**: runs read-then-write work holding the write lock from the start and retries while SQLite is busy.
- **`app.InvalidateSchemaCache`**: call after writing `_moul` with raw SQL; collections that `OnBeforeStart` hooks write directly are served from the first request.
- **Token lifetime**: `MOUL_TOKEN_TTL` / `Config.TokenTTL` (default 24h), per-collection overrides (`MOUL_ROOT_TOKEN_TTL`, `WithCollectionTokenTTL`), and `MOUL_TOKEN_REFRESH_GRACE` (default 7 days). Refreshing now accepts an expired token only within the grace period and only once (it accepted any expired token, repeatedly), and logout revokes a token for its whole refreshable life. Tokens carry a unique `jti`.
- **Configurable API prefix**: `--api-prefix`, `MOUL_API_PREFIX` or `WithAPIPrefix` (default `/api`; `""` mounts at the root).
- **Admin console in custom binaries**: `pkg/app` serves the Web Admin Console at `/_moul_/`; `WithAdminPrefix`, `WithAdminUI` and `DisableAdminUI` move, replace or remove it.
- **Workers**: the worker engine is now public as `pkg/worker`.

## MCP

- **Custom tools**: `RegisterMCPTool` adds tools over stdio and HTTP; `OnMCPInit`, `MCPServer` and `ServeMCP` expose the server; `<custom-binary> mcp` runs stdio MCP without HTTP secrets.
- **OAuth for MCP clients**: RFC 9728 and RFC 8414 discovery, RFC 7591 dynamic client registration and a PKCE authorization code flow (root credentials or the admin key), so Moul connects as a Google Gemini Custom Connected App. `MOUL_APP_NAME` (or `--app-name`, `app_name`) names it.

## Admin console and TUI

- Selects are now combo boxes; the fields builder was reworked with live validation, better default field names and the unique toggle; collections can be deleted from the console.
- `moul-ctl` can update the root account from Settings.

## Upgrade notes

- Admin consoles, scripts and MCP clients must use the admin key or a root user token for the admin endpoints listed above, sent as a header: query-string credentials now get `400`.
- Realtime clients that connected with `?token=` must switch to `?ticket=` or header streaming.
- Clients that relied on `401`/`403` for hidden records now receive `404`.
- Clients that displayed other users' emails must add an `emailVisibility` bool field to the auth collection (or read emails with admin credentials).
- File URLs of non-public records now carry `?sig=` and expire (`MOUL_FILE_URL_TTL`, default 1h); refetch the record for fresh URLs. Make S3 buckets private: Moul now redirects to presigned URLs. Store file field values as returned by `POST /api/upload` (signatures are stripped on write).
- Handle `429` on OTP sign-in (use `reason` to choose between "request a new code" and "wait") and `413` on image uploads over 40 MP (previously `500`).
- Behind a reverse proxy that is not on the same host (another container, a LAN load balancer, Tailscale's `100.64.0.0/10`), set `MOUL_TRUSTED_PROXIES`; otherwise every client shares the proxy's address for rate limits.
- Schemas with snake_case field names are rejected; rename fields to camelCase.
- Scripts that cleared webhooks, email templates or a rule by leaving it out of `PATCH /api/moul/:name` must now send it explicitly (`"webhooks": []`, `"emailTemplates": null`, `"subscribeRule": ""`).
- The `/admin` redirect is gone; open the console at `/_moul_/`.
- Set `MOUL_ENCRYPTION_KEY` before creating `cloak` fields.
- Embedders writing `_moul` with raw SQL outside `OnBeforeStart` should call `app.InvalidateSchemaCache()`; otherwise the change is served within a second.
- No migration of existing databases is provided: files uploaded before this release are not in `_files` and are only served to admins; re-upload them (or reset development databases).
